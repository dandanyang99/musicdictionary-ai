# 音乐词典小程序技术方案

## 1. 项目概述

本项目是一个多语言词典小程序，支持多端开发（微信小程序、支付宝小程序等），提供词典查询、翻译、AI辅助翻译、用户管理等功能。

### 1.1 核心特性

- 多端支持：微信小程序为主，支持其他小程序平台
- 智能翻译：本地词典 → 翻译API → AI翻译的三级查询机制
- AI评估：对翻译结果进行质量评估
- 用户系统：支持多小程序平台的统一用户体系
- 后台管理：完整的管理后台系统

## 2. 技术选型

### 2.1 前端技术栈

**小程序端：uni-app**

选择理由：
- 一套代码，多端运行（微信、支付宝、H5、App等）
- Vue.js语法，学习成本低
- 生态完善，组件库丰富（uView UI）
- 官方维护，更新及时

**后台管理端：Vue 3 + Element Plus**

选择理由：
- Vue 3 Composition API，代码组织更清晰
- Element Plus 组件库完善
- TypeScript 支持，类型安全
- Vite 构建，开发体验好

### 2.2 后端技术栈

**核心框架：Node.js + NestJS + TypeScript**

选择理由：
- **Node.js**：JavaScript全栈，前后端语言统一，开发效率高
- **NestJS**：企业级框架，模块化架构清晰，适合大型项目
- **TypeScript**：类型安全，减少运行时错误，提高代码质量
- **依赖注入**：便于单元测试和模块解耦
- **装饰器语法**：代码简洁，易于维护

**数据库：PostgreSQL 14+**

选择理由：
- 支持JSON/JSONB字段，适合存储多语言词典数据
- 全文搜索功能强大，支持多语言分词
- 支持数组、范围等高级数据类型
- ACID事务支持完善
- 性能优秀，适合高并发场景

**ORM：TypeORM**

选择理由：
- TypeScript原生支持
- 支持多种数据库
- 装饰器语法，与NestJS配合完美
- 支持迁移、种子数据等功能

**缓存：Redis 7+**

选择理由：
- 高性能内存数据库
- 支持多种数据结构（String、Hash、List、Set等）
- 用于缓存词典查询结果，减少数据库压力
- 用于存储用户会话信息
- 支持发布订阅，可用于实时通知

**消息队列：Bull (基于Redis)**

选择理由：
- 轻量级，基于Redis
- 支持延迟任务、定时任务
- 用于异步处理AI翻译、批量导入等耗时操作
- 支持任务优先级和重试机制

### 2.3 AI和翻译API集成

**AI模型接入**

支持多种AI模型，通过统一接口层调用：
- OpenAI GPT-4/GPT-3.5
- 百度文心一言
- 阿里通义千问
- 讯飞星火

**翻译API接入**

支持多种翻译服务，通过统一接口层调用：
- 百度翻译API
- 有道翻译API
- 腾讯翻译API
- Google翻译API（需要代理）

**设计模式：策略模式 + 工厂模式**

```typescript
// 统一的AI接口
interface AIProvider {
  translate(text: string, from: string, to: string): Promise<string>;
  evaluate(translation: string, context: any): Promise<number>; // 返回评分0-100
}

// 统一的翻译接口
interface TranslationProvider {
  translate(text: string, from: string, to: string): Promise<string>;
}
```

### 3.2 核心业务流程：词典查询

```
用户输入单词 → 选择源语言和目标语言
         ↓
    查询Redis缓存
         ↓
    ┌────┴────┐
    │ 缓存命中？│
    └────┬────┘
         │
    否   │   是
    ↓    │    ↓
查询本地词典  │  返回缓存结果
    ↓    │
┌───┴────┐│
│词典有数据？││
└───┬────┘│
    │     │
否  │  是 │
↓   │   ↓ │
调用翻译API  返回词典结果
    ↓        ↓
AI评估翻译质量  写入缓存
    ↓
┌───┴────┐
│评分>=80？│
└───┬────┘
    │
是  │  否
↓   │   ↓
返回翻译结果  调用AI翻译
    ↓        ↓
写入缓存    返回AI翻译
    ↓        ↓
  (可选)保存到词典
```

**查询策略说明：**

1. **第一级：Redis缓存**
   - 缓存key格式：`dict:{word}:{from}:{to}`
   - 缓存时间：24小时
   - 命中率预期：60-70%

2. **第二级：本地词典**
   - PostgreSQL全文搜索
   - 支持模糊匹配
   - 查询时间：<50ms

3. **第三级：翻译API**
   - 轮询多个翻译服务
   - 失败自动切换备用服务
   - 超时时间：5秒

4. **第四级：AI翻译**
   - 仅在翻译API评分不达标时调用
   - 异步处理，避免阻塞
   - 超时时间：10秒

## 4. 数据库设计

### 4.1 核心数据表

**用户表 (users)**

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  phone VARCHAR(20) UNIQUE NOT NULL,
  nickname VARCHAR(50),
  avatar VARCHAR(255),
  email VARCHAR(100),
  gender SMALLINT, -- 0:未知 1:男 2:女
  birthday DATE,
  address TEXT,
  preferred_language VARCHAR(10) DEFAULT 'zh-CN',
  status SMALLINT DEFAULT 1, -- 1:正常 0:禁用
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_phone ON users(phone);
CREATE INDEX idx_users_status ON users(status);
```

**用户平台绑定表 (user_platform_bindings)**

```sql
CREATE TABLE user_platform_bindings (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  platform VARCHAR(20) NOT NULL, -- 'wechat', 'alipay', etc.
  open_id VARCHAR(100) NOT NULL,
  union_id VARCHAR(100),
  app_id VARCHAR(50) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(platform, open_id, app_id)
);

CREATE INDEX idx_upb_user_id ON user_platform_bindings(user_id);
CREATE INDEX idx_upb_platform_openid ON user_platform_bindings(platform, open_id);
```

**语言表 (languages)**

**词典表 (dictionary_entries)**

```sql
CREATE TABLE dictionary_entries (
  id SERIAL PRIMARY KEY,

  source_lang VARCHAR(10) REFERENCES languages(code),
  target_lang VARCHAR(10) REFERENCES languages(code),
  translation TEXT NOT NULL,
  phonetic VARCHAR(100), -- 音标
  definition TEXT, -- 释义
  examples JSONB, -- 例句 [{"source": "...", "translation": "..."}]

  created_by INTEGER REFERENCES users(id),
  status SMALLINT DEFAULT 1,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_dict_word ON dictionary_entries(word, source_lang, target_lang);
CREATE INDEX idx_dict_langs ON dictionary_entries(source_lang, target_lang);
CREATE INDEX idx_dict_quality ON dictionary_entries(quality_score);
```

## 5. API设计

### 5.1 RESTful API规范

**基础URL**
- 开发环境：`http://localhost:3000/api/v1`
- 生产环境：`https://api.yourdomain.com/api/v1`

**统一响应格式**

```typescript
// 成功响应
{
  "code": 0,
  "message": "success",
  "data": { ... }
}

// 错误响应
{
  "code": 1001,
  "message": "错误描述",
  "error": "详细错误信息"
}
```

**状态码规范**
- 0: 成功
- 1001-1999: 客户端错误（参数错误、权限不足等）
- 2001-2999: 服务端错误（数据库错误、第三方服务错误等）
- 3001-3999: 业务逻辑错误（用户不存在、词典未找到等）

## 6. 部署方案

### 6.1 开发环境

**环境要求**
- Node.js 18+
- PostgreSQL 14+
- Redis 7+
- 微信开发者工具

**本地开发步骤**

```bash
# 1. 克隆项目
git clone <repository-url>

# 2. 安装后端依赖
cd backend
npm install

# 3. 配置环境变量
cp .env.example .env
# 编辑 .env 文件，配置数据库、Redis等

# 4. 运行数据库迁移
npm run migration:run

# 5. 启动后端服务
npm run start:dev

# 6. 安装前端依赖（小程序）
cd ../miniapp
npm install

# 7. 启动小程序开发
# 使用微信开发者工具打开 miniapp 目录

# 8. 安装管理后台依赖
cd ../admin
npm install

# 9. 启动管理后台
npm run dev
```

### 6.2 生产环境部署

**服务器配置建议**
- CPU: 4核+
- 内存: 8GB+
- 硬盘: 100GB+ SSD
- 带宽: 5Mbps+

**Docker部署（推荐）**

```yaml
# docker-compose.yml
version: '3.8'

services:
  postgres:
    image: postgres:14
    environment:
      POSTGRES_DB: musicdict
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  backend:
    build: ./backend
    environment:
      NODE_ENV: production
      DATABASE_URL: postgresql://admin:${DB_PASSWORD}@postgres:5432/musicdict
      REDIS_URL: redis://redis:6379
    ports:
      - "3000:3000"
    depends_on:
      - postgres
      - redis

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - backend

volumes:
  postgres_data:
  redis_data:
```

**部署命令**

```bash
# 构建并启动服务
docker-compose up -d

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down
```

## 9. 安全性考虑

### 9.1 认证与授权

**JWT Token机制**
- Access Token: 有效期2小时
- Refresh Token: 有效期7天
- Token存储在HTTP-only Cookie中，防止XSS攻击

**权限控制**
- 使用RBAC（基于角色的访问控制）
- 角色：超级管理员、管理员、普通用户
- 使用NestJS Guard进行权限验证

### 9.2 数据安全

**敏感数据加密**
- 密码使用bcrypt加密，加盐轮次10
- API密钥使用AES-256加密存储
- 数据库连接使用SSL

**SQL注入防护**
- 使用TypeORM参数化查询
- 禁止拼接SQL语句

**XSS防护**
- 前端输入进行HTML转义
- 使用Content-Security-Policy头

**CSRF防护**
- 使用CSRF Token
- 验证Referer头

### 9.3 API安全

**请求限流**
- 使用Redis实现分布式限流
- 普通用户：100次/分钟
- 管理员：1000次/分钟

**API密钥管理**
- 定期轮换API密钥
- 使用环境变量存储密钥
- 不在代码中硬编码密钥

## 10. 性能优化

### 10.1 缓存策略

**多级缓存**
1. Redis缓存：热门词典查询结果
2. 应用层缓存：配置信息、语言列表
3. CDN缓存：静态资源

**缓存更新策略**
- 词典查询结果：24小时过期
- 配置信息：手动刷新
- 使用Cache-Aside模式

### 10.2 数据库优化

**索引优化**
- 为常用查询字段添加索引
- 使用复合索引优化多条件查询
- 定期分析慢查询日志

**查询优化**
- 使用分页查询，避免一次性加载大量数据
- 使用连接查询代替N+1查询
- 使用数据库连接池

### 10.3 异步处理

**消息队列**
- AI翻译任务异步处理
- 批量导入词典异步处理
- 邮件发送异步处理

**并发控制**
- 使用Bull队列控制并发数
- 避免同时调用过多AI API
